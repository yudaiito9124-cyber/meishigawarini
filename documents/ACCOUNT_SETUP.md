# 共同開発にあたってのAWS環境・権限設定ガイド

本プロジェクトでは、**AWS CDK (v2)** および **AWS Amplify** を中心としたサーバーレス構成を採用しています。チームメンバーが安全かつ効率的に開発を進めるための設定手順を以下にまとめます。

---

## 1. AWSアカウントの基本構造（親子関係）
本プロジェクトでは、1つの **AWSメインアカウント** を共有し、その中に開発者ごとの **IAMユーザー** を作成して運用します。

* **メインアカウント (親)**: 
    * 支払い（請求）が一括管理される場所。
    * DynamoDB, S3, Cognito などの実リソースが存在する場所。
* **IAMユーザー (子)**: 
    * 開発者個人のログインID。
    * 「誰がどの操作をしたか」を識別するために、開発者ごとに作成します。
    * **注意**: 開発者自身が個別に「新しいAWSアカウント」を新規作成する必要はありません。

## 2. 新規開発者をプロジェクトに招待する手順（管理者向け）

新しいメンバーがプロジェクトに参加する場合、**管理者（オーナー）**が以下の作業を行う必要があります。
※ご自身が新規参加者で、まだ権限をもらっていない場合は、管理者に招待を依頼してください。

### 必要な情報の共有・招待
管理者は新規メンバーに対して以下を用意し、Slack等の安全なツールで渡してください。
1.  **GitHubリポジトリの招待**: [yudaiito9124-cyber/meishigawarini](https://github.com/yudaiito9124-cyber/meishigawarini) への Write 権限付き招待。
2.  **AWS IAMユーザーの発行**: (手順は後述) 発行された `ログインURL` `ユーザー名` `初期パスワード`。
3.  **環境変数 (`.env.local` / `.env`)**: API URLや各種シークレットなどの動作に必要な設定値。
4.  *(必要に応じて)* **Resend (メール送信) のテスト用APIキー**

### AWS認証環境の発行手順 (管理者のAWSコンソール作業)

本プロジェクトではセキュリティ強化のため、アクセスキーの直接発行ではなく **AWS IAM Identity Center (旧SSO)** などを用いた一時的な認証情報の利用を推奨しています。

1.  AWS IAM Identity Center 等で新規ユーザーを作成します。
2.  作成したユーザーを適切な権限（`AdministratorAccess` 相当や各種開発用グループ）を持つグループに割り当てます。
3.  完了画面等で発行される **「AWS アクセスポータル URL（またはスタートURL）」「ユーザー名」「初期パスワード」** をメンバーに共有してください。

---

## 3. 開発者側（メンバー）が行う初期設定

共有されたログイン情報（スタートURL等）を受け取ったら、自身のPCからAWSを操作できるようにセットアップします。

### ① AWS CLIのインストールと認証（SSOログイン）
ローカル環境からCDKコマンド等を実行するために必要です。
1.  [AWS CLI](https://aws.amazon.com/jp/cli/) をインストール。
2.  ターミナルで以下のコマンドを実行し、ブラウザでログインプロセスを完了させます。
    ```bash
    aws login
    ```
    *※初回設定時や、SSO環境が未構築の場合は、管理者に共有されたスタートURLを用いて `aws configure sso` コマンドで初期セットアップを完了させてから `aws login` を実行してください。*

### ② CDK Bootstrap の実行
その環境（リージョン）で初めてCDKを使う際、デプロイ用の管理リソース（S3バケット等）を作成する必要があります。
```bash
npx cdk bootstrap
```
